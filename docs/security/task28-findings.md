# Task 28 — Security findings register

Assessment baseline: `main` commit `ff290289488378ff1b70ebabac66f3fefa0da937`; remediation branch `task/28-security-privacy-audit`. Latest code verification: [CI run #979](https://github.com/sepehrsamad1/kouhfar-dental/actions/runs/41684593114), revision `3282ab38d55df8d3b5cd7cb01a70ed6aada4821c`. Earlier finding-specific retests remain cited at their original runs.

Severity meanings for this register:
- **Critical:** direct compromise or broad unauthorized disclosure/control with severe impact.
- **High:** material risk to patient/staff data or core security boundary; blocks release.
- **Medium:** meaningful weakness with bounded exploitability/impact; must be fixed or explicitly accepted before production.
- **Low:** defense-in-depth or operational improvement.

## Release decision

**BLOCK RELEASE.** SEC-28-003 remains high and open: consent/Smart Smile, queue/failed-job, notification outbox and deletion-request retention rules remain undecided; separate backup storage/key/ACLs, monitoring and full isolated recovery evidence are still missing. Patient/CRM records and original audit logs are owner-approved for indefinite retention and must not be automatically purged. SEC-28-012 is remediated in branch and CI-verified in run #937; the lost-authenticator/reset process remains an operational rollout item. SEC-28-005 automated scans have passed in CI run #937; supplementary secret-surface review remains open at medium severity. Medium findings SEC-28-004, SEC-28-006, SEC-28-007, SEC-28-008, SEC-28-014 and SEC-28-015 also remain open. No critical finding was confirmed from the reviewed source, but this is not equivalent to a complete penetration test. The booking OTP challenge lifecycle and approved limits are implemented and covered by synthetic tests. MeliPayamak remains disabled by default; live activation requires deployment secret injection, provider/network URL-path log review and separate clinic approval. OTP challenge metadata retention remains open under OD-28-18.

Do not test production or third-party systems without written authorization. Do not use real patient data or credentials in CI.
