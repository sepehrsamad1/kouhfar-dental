## Network egress review

The inspected `config/services.php` is empty. No real AI provider is configured; the AI provider manager uses the fake adapter unless explicitly configured. The transactional SMS manager contains a dormant Kavenegar adapter. The OTP manager contains a MeliPayamak adapter, disabled by default; no live configuration or credential has been installed. No user-controlled URL-fetch feature was found in the reviewed controllers/services. The dormant Kavenegar adapter uses Laravel's HTTP client and its API key is part of the request path. The MeliPayamak OTP adapter uses a fixed HTTPS origin and places its provider token in the endpoint path, read only from `MELIPAYAMAK_OTP_TOKEN` at runtime. Task 28 now restricts the configured endpoint to the exact HTTPS origin `api.kavenegar.com:443` and `/v1` path, rejects userinfo/query/fragment, disables redirects, applies a bounded timeout and returns generic transport failures without chaining request exceptions that could reveal the key. Synthetic tests cover unapproved hosts (including a metadata IP), redirect attempts and exception secrecy. No live provider request was made. Provider activation still requires clinic approval of the vendor and data flow; MeliPayamak booking OTP also requires an approved code lifetime, attempt limit and resend/rate-limit policy.

Therefore SSRF is **not demonstrated in the current configured runtime**, not a claim that future network integrations are inherently safe. Any future HTTP client must use fixed allow-listed destinations, strict TLS verification, bounded timeouts/response sizes, redirect restrictions, and must not accept user-controlled full URLs.

## Approval gate

No third-party service that receives patient identifiers, patient images, appointment details, clinical notes, AI prompts containing personal data, or phone numbers may be activated until the clinic has approved the exact vendor and data flow in writing.
